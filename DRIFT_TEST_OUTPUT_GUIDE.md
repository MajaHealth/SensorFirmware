# Drift Test Output Files - Complete Reference Guide

This guide explains all output files generated by `test_icg_ecg_drift_1hour.py` and the meaning of every column in the CSV files.

## Overview

The enhanced drift test generates **4 output files** for comprehensive debugging:

| File | Purpose | Rows | Columns |
|------|---------|------|---------|
| **requests_log_*.csv** | Every get_data request/response | ~18,000 (1 per 0.2s) | 20 |
| **sync_analysis_*.csv** | Per sync marker analysis | ~3,600 (1 per second) | 35 |
| **anomalies_report_*.txt** | Human-readable summary | N/A (text) | N/A |
| **icg_ecg_drift_1hour_results_*.json** | Complete structured data | N/A (JSON) | N/A |

## File 2: sync_analysis_YYYYMMDD_HHMMSS.csv

**Purpose:** Analyzes each sync marker pair (ICG and ECG) with sample-accurate timing, sample counts between markers, and drift tracking.

**Use case:** Validate 400 samples between markers, track drift accumulation, identify missing sync markers.

| Column | Type | Description | Example |

#### ICG Sync Marker Details (12 columns)

| Column | Type | Description | Example |
|--------|------|-------------|---------|
| **icg_found** | Boolean | Was this sync marker found in ICG stream? | `TRUE` |
| **icg_request_id** | Integer | Which request contained this sync marker | `954` |
| **icg_request_time_utc** | ISO DateTime | UTC time when request was made | `2025-10-28T10:48:33.234567` |
| **icg_firmware_timestamp** | Float | Firmware timestamp of packet containing sync | `1730113713.594123` |
| **icg_position_in_packet** | Integer | Position of sync marker in packet (0-based index) | `41` |
| **icg_total_samples_in_packet** | Integer | Total samples in this packet | `82` |
| **icg_samples_before_sync** | Integer | Samples before sync marker in packet | `41` |
| **icg_samples_after_sync** | Integer | Samples after sync marker in packet | `40` |
| **icg_calculated_timestamp** | Float | Sample-accurate timestamp of sync marker | `1730113713.491623` |
| **icg_samples_since_last_sync** | Integer | Samples between this sync and previous sync | `400` |
| **icg_sample_deviation** | Integer | Deviation from expected 400 samples (±) | `0` or `-12` |
| **icg_time_since_last_sync** | Float | Time interval since last sync (seconds) | `1.000` |

**Note on icg_calculated_timestamp:**
- Firmware timestamp points to the **end** of the packet (last sample received)
- To get sample-accurate sync timestamp: `firmware_ts - (samples_after_sync / sampling_rate)`
- Example: If sync at position 41 in 82-sample packet at time 1730113713.594
  - samples_after_sync = 40
  - time_offset = 40 / 400 Hz = 0.1 seconds
  - calculated_timestamp = 1730113713.594 - 0.1 = 1730113713.494

| Pattern | Meaning | Action |
|---------|---------|--------|
| **icg_sample_deviation ≠ 0** | Not exactly 400 samples between syncs | Sample drops or buffering issue |

## Understanding Sample-Accurate Timestamps

The drift test calculates **sample-accurate timestamps** for sync markers, accounting for their position within the data packet.

### Why This Matters

Firmware timestamps indicate when the **last sample** in the packet was captured, not when the sync marker occurred. For precise drift analysis, we need to know **exactly when** the sync marker was sampled.

### Calculation

```
calculated_timestamp = firmware_timestamp - (samples_after_sync / sampling_rate)
```

### Example

**Scenario:**
- Firmware timestamp: `1730113713.594` (last sample in packet)
- Sync marker position in packet: `41` (0-based index)
- Total samples in packet: `82`
- Sampling rate: `400 Hz`

**Calculation:**
```
samples_after_sync = 82 - 41 - 1 = 40
time_offset = 40 / 400 = 0.100 seconds
calculated_timestamp = 1730113713.594 - 0.100 = 1730113713.494
```

**Result:** The sync marker actually occurred 100ms **before** the packet timestamp.

### Impact on Drift Measurement

Without sample-accurate timestamps:
- Drift measurements would vary ±100ms randomly depending on sync position
- True drift would be masked by packet timing noise

With sample-accurate timestamps:
- Drift measurements are accurate to <1ms
- Real timing issues are clearly visible

## Common Debugging Scenarios

### Scenario 1: Multiple Syncs in Single Packet

**Symptoms:**
```csv
request_id,icg_sync_count,icg_sync_numbers,anomaly_multiple_icg_syncs
145,2,"145,146",TRUE
289,3,"289,290,291",TRUE
```

**Meaning:** Buffer overflow - firmware couldn't flush data fast enough, accumulated 2-3 seconds worth of data in one packet.

**Root cause:**
- Request interval too slow (e.g., 1 second instead of 0.2 seconds)
- Firmware buffer not being cleared properly
- System under heavy load

**Fix:**
- Increase request frequency (reduce data_interval)
- Increase firmware buffer size
- Check system CPU usage

---

### Scenario 2: Sample Count Deviation

**Symptoms:**
```csv
sync_num,icg_samples_since_last_sync,icg_sample_deviation,anomaly_icg_sample_count
5041,387,-13,TRUE
5042,412,+12,TRUE
5043,395,-5,FALSE
```

**Meaning:** Not consistently getting 400 samples between 1-second sync markers.

**Root causes:**
- **Negative deviation (-13):** Sample drops - data lost
  - Buffer overflow
  - SPI communication errors
  - DMA buffer overruns

- **Positive deviation (+12):** Extra samples
  - Sync injection timing off
  - Double counting at boundaries
  - Sample rate misconfiguration

**Fix:**
- Check firmware buffer management
- Verify SPI timing and DMA configuration
- Validate sync injection occurs exactly every 1 second

---

### Scenario 3: Missing Sync Markers

**Symptoms:**
```csv
sync_num,icg_found,ecg_found,paired,anomaly_icg_missing
5040,TRUE,TRUE,TRUE,FALSE
5041,FALSE,TRUE,FALSE,TRUE
5042,TRUE,TRUE,TRUE,FALSE
```

**Meaning:** Sync marker 5041 present in ECG but missing from ICG.

**Root causes:**
- Firmware failed to inject sync marker at that second
- Sync marker was dropped due to buffer overflow
- Firmware timing loop skipped

**Fix:**
- Check firmware sync injection code
- Verify timing loop runs consistently every second
- Check for buffer flow issues

---

### Scenario 4: Growing Drift Over Time

**Symptoms:**
```csv
sync_num,time_diff_ms,drift_cumulative_ms
5040,2.3,45.6
5041,2.5,48.1
5042,2.7,50.8
5043,2.9,53.7
```

**Meaning:** Drift between ICG and ECG is **increasing** over time (time_diff_ms getting larger).

**Root causes:**
- Clock drift between devices
- Asynchronous firmware timing loops
- One device running faster than expected

**Fix:**
- Synchronize clocks
- Use shared timer for sync injection
- Verify both devices use same clock source

---

### Scenario 5: Inconsistent Time Intervals

**Symptoms:**
```csv
sync_num,icg_time_since_last_sync,anomaly_time_interval
5040,1.000,FALSE
5041,1.053,TRUE
5042,0.947,TRUE
5043,1.000,FALSE
```

**Meaning:** Sync markers not being injected at **consistent 1-second intervals**.

**Root causes:**
- Firmware timing loop jitter
- System load affecting timing
- Timer resolution issues

**Fix:**
- Use hardware timer for sync injection
- Reduce system load
- Verify timer configuration and resolution

## Quick Reference: Anomaly Threshold

| Anomaly Type | Threshold | Description |
|--------------|-----------|-------------|
| **Sample count deviation** | ±20 samples | More than 5% deviation from expected 400 |
| **Time interval deviation** | ±50 ms | More than 5% deviation from expected 1.0s |
| **Multiple syncs** | >1 per packet | Any packet with 2+ sync markers |
| **Missing data** | 0 samples | Any request returning no data |
| **Drift threshold** | 50 ms (configurable) | Time difference between ICG and ECG sync |

## Loading Data for Analysis

### Python with Pandas

```python
import pandas as pd

# Load request log
requests = pd.read_csv('requests_log_20251028_103000.csv')
print(f"Total requests: {len(requests)}")
print(f"Anomalies: {requests['anomaly_multiple_icg_syncs'].sum()}")

# Load sync analysis
syncs = pd.read_csv('sync_analysis_20251028_103000.csv')
print(f"Total syncs: {len(syncs)}")
print(f"Paired syncs: {syncs['paired'].sum()}")
print(f"Mean drift: {syncs['time_diff_ms'].mean():.3f} ms")

# Filter anomalies
icg_issues = syncs[syncs['anomaly_icg_sample_count'] == True]
print(f"ICG sample count issues: {len(icg_issues)}")
print(icg_issues[['sync_num', 'icg_samples_since_last_sync', 'icg_sample_deviation']])
```
